## 2. Where the source and the tree disagree, and how it was decided

1. **Input mode** (`ConsoleShell`, `DataTable`; handoff item 1). The compile imports `useInputMode`
   from Strand's `core/InputMode.jsx`, which the tree has never carried. Both parts read `useMode()`
   from `src/lib/tier.ts`, the app's one input-mode source, as Tooltip, PostCard, Menu and LensBar
   do. `useMode` answers `"touch" | "pointer"` from `(pointer: coarse)` and follows its changes, the
   same vocabulary the parts' `input` prop declares, so nothing is mapped at the call site. The
   known cost every port carries: `useMode` reads `"pointer"` until its effect runs, so the
   server-rendered form is the pointer form and a touch device's DataTable rows grow from 40 to 48
   on hydration unless `input` is given.
2. **ConsoleShell's tier** (handoff item 2). The compile's `useTier` reads `--tier-medium` and
   `--tier-expanded` off the shell's own element in a ResizeObserver and returns
   `w < m ? compact : w < x ? medium : expanded`, so a shell measuring exactly 1024 is expanded.
   Its own doc comment and the extraction say expanded is _over_ `--tier-expanded`, and `tierFor()`
   in `src/lib/tier.ts` returns medium at 1024 (`width > 1024` is expanded). The port keeps the
   compile's shape, the shell's own `clientWidth` in a ResizeObserver, and hands the width to
   `tierFor()`, so the app has one tier rule and the one pixel falls on the ruled side: at exactly
   1024 the compile renders the left navigation and the port renders the opener and drawer. A
   given `tier` wins, as compiled, and the first render before measurement is expanded, as compiled.
   The compile's fallbacks of 640 and 1024 when the tokens do not parse are `tierFor()`'s constants,
   which are the tokens' values (`--tier-medium: 640px`, `--tier-expanded: 1024px`).
3. **Hook dependencies** (`ConsoleShell`'s drawer). The compile keys both of ConsoleMenu's effects
   on `[open]` alone. The port keeps that and says why above each `eslint-disable-next-line`, as
   Composer does: keying the key-listener effect on `onClose` too, which ConsoleShell passes as a
   fresh arrow each render, would re-capture `document.activeElement` while the drawer is open and
   return focus inside the drawer instead of to the opener. Not visible; behaviour as compiled.
4. **Focus return** (`ConsoleShell`'s drawer; ruling 1366, handoff 45-B item C4). Section 7 below
   recorded the compile's defect: ConsoleMenu's passive effect captured `document.activeElement`
   after its layout effect had moved focus to the drawer's Close button, so Escape left focus on
   the body. The port now captures the active element in the layout effect, before the focus call,
   in a ref, and the key-listener effect's cleanup returns focus to it when it is still in the
   document. This is the one behavioural divergence from the compile, named in the file's header
   as item 3; the fix belongs to the Strand part as well, and this record is where Design reads it.
   Arm C-a (`tests/overview.cjs`) opens the drawer at 390 and 820 on the admin preview, presses
   Escape and asserts focus is on the opener.

## 3. Lines rewritten to the same value under the tree's compiler options

`noUncheckedIndexedAccess` and `noPropertyAccessFromIndexSignature` are on, so an indexed read is
`T | undefined` and a `Record<string, unknown>` row is read with brackets. Where that forced a
rewrite, the value is the compile's:

- `Sparkline`: the area path's two closing x values are written as `pad` and `pad + (w - 2 * pad)`
  where the compile reads `pts[0][0]` and `pts[pts.length - 1][0]`; the points are built from those
  expressions on the line above, so the strings are identical.
- `StackedBars`: `sums[k]` is read into a local before `!= null`; `INKS[k]` passes as
  `string | undefined` to `fill`, which accepts it.
- `BarList`: `r.value` is read into a local so the null narrowing holds through `off`.
- `DataTable`: rows are `Record<string, unknown>`; `r["id"]` keys the row when it is a string or a
  number, else the index (the compile's `r.id || i`); a cell's value is `c.render(v, r)`, a
  localised number when numeric, else the value as a node.
- `DiaNote`: the ghost widths `["92%", "78%", "85%"][i]` pass as `string | undefined` to `width`.
- `ConsoleShell`: `d && d.getBoundingClientRect()` and the focus calls are `if` statements
  (`@typescript-eslint/no-unused-expressions`); `prev && prev.focus && prev.focus()` is
  `if (prev instanceof HTMLElement) prev.focus()`; the compile's internal `useTier` is named
  `useShellTier` so it does not shadow `src/lib/tier.ts`'s `useTier`, and the unused `tr` local and
  the `tier` prop ConsoleMenu never read are not carried.
- `ConsoleShell`: `staff` is required, as the `.d.ts` declares it; the compile's `staff = {}`
  default is not carried.

1. Arm 1 names "whatever harness the repo already uses for Strand parts". That harness is the mount
   arms in `tests/mount.cjs`, which read a part off the deployed page that binds it, and
   `scripts/token-check.mjs`, which proves every cited token is declared in both themes. No page
   binds the seven: the admin app's binding is the 12B handoff's decision (item 6) and the member

   `v1790410319010950`'s record shows the same gap for BodyBlocks, PersonCard and BrowseTile
   ("ported; no page binds them"), which then had no render arm at all. This port adds
   `tests/strand-admin.cjs`: it loads the barrel through Vite's SSR module loader, the transform the
   app's server build runs, renders every part in every state through `react-dom/server`, records a
   throw as a failed check, reads off the seven sources that none branches on `data-theme` or
   `prefers-color-scheme`, and carries arm 2. It runs in `pages.yml`'s deploy job beside the token
   check, which is the other half of "both themes". What it does not prove: the client effects
   (ConsoleShell's ResizeObserver, the drawer's `dialog.show()`, focus trap and transition,
   DataTable's hover and sort clicks), which no arm reaches until a page binds the parts.
2. Arm 3 names "the seven parts' component names". The production build minifies identifiers:
   `DiaLine`, `PostCard` and `LensBar` are in no file under `dist/`, while a string a part carries
   (`strand-breathe`) is, so a name alone would pass on a bundle that shipped the part. The member
   half of `tests/admin-bundles.cjs` checks the seven names and, for each, one or two strings read
   off the part's own rendering that exist in no member surface, and first checks every pairing
   against the part's source so a stale marker fails by name. StackedBars and DiaNote name
   themselves inside a console warning, so for those two the name is a real string as well.
3. Item 1 anticipated that Strand's `useInputMode` might return a different vocabulary. It does not:
   the parts' `input` prop and `useMode` both read `"touch" | "pointer"`, so nothing is mapped.

One check failed at every width below expanded, and it is the compile's, ported as compiled (844):
**after Escape, focus does not return to the opener.** ConsoleMenu's layout effect moves focus to
the drawer's first focusable (Close) before its passive effect captures `document.activeElement`
as the element to return to, so the captured element is Close, which unmounts with the drawer
`--dur-slow` later and leaves focus on the body. The extraction's pointer contract says "focus
returns to the opener"; the source does not deliver it. A scratch probe that captured the active
element in the layout effect, before the focus call, returned focus to the opener at every width,
and was reverted: a port carries the compile's behaviour, and the fix belongs to the Strand part.
